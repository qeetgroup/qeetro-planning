## Content

### Description
Add GitHub Actions CI that runs install, typecheck, lint, format-check, unit tests, integration tests against Postgres/Redis service containers, Prisma migration check, and builds for every PR.

### Business Context
The `main` (or `develop`) branch must stay releasable. CI is the only enforcement layer for the conventions established in PF-002/PF-003/PF-008. Without it, broken merges land and erode confidence.

### Problem Statement
No CI exists. The first PR that introduces real source (likely PF-004 or PF-005) needs CI to be in place to prevent regressions immediately.

### Scope
- `.github/workflows/ci.yml`:
  - Trigger on `pull_request` and `push` to `develop` and `main`.
  - Job `setup`: checkout, set up Node 20 LTS, install pnpm via `pnpm/action-setup`, cache pnpm store + `node_modules`.
  - Job `lint`: depends on `setup`, runs `pnpm lint` and `pnpm format:check`.
  - Job `typecheck`: depends on `setup`, runs `pnpm -r typecheck`.
  - Job `unit`: depends on `setup`, runs `pnpm -r test`.
  - Job `integration`: depends on `setup`, uses GitHub service containers for `postgres:16-alpine` and `redis:7-alpine`, runs Prisma migration deploy + `pnpm -r test:integration` (placeholder once tests exist).
  - Job `build`: depends on `setup`, runs `pnpm -r build`.
  - Job `db-migration-check`: validates that any migration in this PR also has a corresponding `schema.prisma` change and not the other way around (script in `scripts/check-migration.sh`).
  - All jobs must pass before merge.
- Branch protection note in PR description for the maintainer to enable on `develop` and `main` (this is not automatable in Actions — record it as a manual checklist item).
- Concurrency group: cancel in-progress runs for the same PR.

### Technical Notes
- Use `actions/checkout@v4`, `actions/setup-node@v4`, `pnpm/action-setup@v4`, `actions/cache@v4` (pinned to versions in use as of May 2026).
- Service containers expose 5432/6379 to the runner; jobs read `DATABASE_URL` and `REDIS_URL` from env.
- Avoid running e2e Next.js tests in CI for now; Playwright comes in Sprint 9 (QA-001).
- Total CI walltime budget: under 6 minutes on a typical PR.

### Security Considerations
- Do not echo secrets in logs.
- Use `permissions: contents: read` at the workflow level; expand only per job that needs more.
- No third-party action without a pinned commit SHA (pin major versions for first-party `actions/*`, full SHA for community actions).

### Performance Considerations
- pnpm store cache key keyed on `pnpm-lock.yaml` hash.
- `actions/setup-node` cache for `pnpm` reduces install time to under 1 minute on warm cache.

### Edge Cases
- A PR that only changes docs should still run `lint` and `format:check` but skip `integration` and `build`. Use `paths-ignore` carefully (better: keep all jobs running and rely on cache to keep them fast).
- A forked PR must not have access to secrets — explicitly verify default behavior.

## Delivery

### Acceptance Criteria
- [ ] `.github/workflows/ci.yml` committed and runs on every PR.
- [ ] All jobs pass on a clean PR.
- [ ] An intentional `: number = "foo"` TypeScript error fails the `typecheck` job.
- [ ] An intentional unused import fails the `lint` job.
- [ ] Removing a column from a migration without updating `schema.prisma` is rejected by `db-migration-check`.
- [ ] CI walltime under 6 minutes on warm cache (record observed time in PR description).
- [ ] Workflow uses `permissions: contents: read` by default.

### Testing Requirements
- Use the integration job to assert Prisma migrations apply cleanly against the service container.
- Maintainer to verify branch-protection is enabled on `develop` and `main` once the workflow is green.

### Definition of Done
- Branch merged into `develop`.
- README in `.github/workflows/` (or root) explains which jobs are required for merge.
- Sprint 1 board column updated to Done.
