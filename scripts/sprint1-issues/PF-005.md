## Content

### Description
Create the NestJS API shell for `apps/api` so every future backend module has a consistent module pattern, validation, exception handling, and health endpoint.

### Business Context
The API is the system of record for qeetro. Identity, tenancy, and the entire work-core domain in Sprints 2–4 will plug into this shell. It must be opinionated and consistent from day one to avoid per-module reinvention.

### Problem Statement
There is no API yet. We need a NestJS application that boots, exposes `/api/v1/healthz`, validates DTOs with `class-validator`, and exception-filters all errors into a typed response.

### Scope
- NestJS 10+ application under `apps/api`.
- Application bootstrap in `src/main.ts`:
  - Global `ValidationPipe` (`whitelist`, `forbidNonWhitelisted`, `transform`).
  - Global exception filter mapping unhandled errors to a typed JSON shape.
  - Global API prefix `/api/v1`.
  - Helmet, compression, basic CORS placeholder.
- Modules:
  - `AppModule` (composition root).
  - `ConfigModule` reading typed env from `packages/config` (created in PF-011).
  - `HealthModule` exposing `GET /api/v1/healthz` and `GET /api/v1/readyz` (placeholder ready check until PF-007/PF-008 land).
- DTOs use `class-validator` + `class-transformer`.
- Typed error response shape: `{ code, message, details?, requestId }`.
- Logger placeholder hooked from `packages/logger` (created in PF-012).
- Test setup:
  - `apps/api/test/e2e/health.e2e-spec.ts` (smoke).
  - `apps/api/test/unit/` scaffolding.
- TypeScript config extends `packages/tsconfig/nestjs.json`.

### Technical Notes
- Use NestJS `Fastify` adapter for performance, or stick with default Express — pick one and record in an ADR if Fastify (default to Express for v1).
- Avoid registering any real domain module yet — Sprint 2 introduces Identity.
- No database connection yet — that lands in PF-008.

### UX Notes
N/A — backend only.

### API Notes
- All routes are versioned under `/api/v1`.
- Health endpoint returns: `{ status: "ok", uptimeSeconds, version, gitSha }`.
- Errors return the typed shape consistently.

### Database Notes
- No schema, no Prisma client wired in this issue.

### Security Considerations
- Helmet enabled with defaults.
- CORS allowlist defaults to `http://localhost:3000` for local dev; production allowlist is configured later.
- Do not log request bodies until logger sanitization is in place (PF-012).

### Performance Considerations
- API cold-start under 2 seconds in dev mode.
- p99 latency under 50 ms on `/healthz` locally.

### Edge Cases
- Unhandled promise rejection must crash the process cleanly (let the supervisor restart it) rather than silently log.
- Validation errors must return 400 with the typed shape, not 500.
