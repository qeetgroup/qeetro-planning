## Content

### Description
Add a Docker Compose configuration that boots PostgreSQL and Redis locally with health checks and zero-secrets defaults so any contributor can run the stack with one command.

### Business Context
Local development must be reproducible. Without Compose, every developer (today: one, tomorrow: many) sets up databases differently and "works on my machine" bugs leak into CI. Postgres and Redis are required by every domain past Sprint 1.

### Problem Statement
There is no way to run Postgres or Redis locally today. The API shell (PF-005) and Prisma foundation (PF-008) cannot do useful work until these services exist.

### Scope
- `infra/docker/docker-compose.yml` with services:
  - `postgres` (image `postgres:16-alpine`, named volume, port 5432, health check via `pg_isready`).
  - `redis` (image `redis:7-alpine`, named volume, port 6379, health check via `redis-cli ping`).
- `infra/docker/.env.example` listing required variables (`POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`, `REDIS_PASSWORD` optional).
- Repo-root scripts in `package.json`:
  - `db:up` → `docker compose -f infra/docker/docker-compose.yml up -d`
  - `db:down` → `docker compose -f infra/docker/docker-compose.yml down`
  - `db:logs` → `docker compose -f infra/docker/docker-compose.yml logs -f`
  - `db:reset` → `down -v` + `up -d`
- Documented in `infra/docker/README.md` with quick-start commands.
- Named volumes for both services so data survives container restarts.
- Containers attach to a single user-defined network `qeetro_local`.

### Technical Notes
- Pin image versions; never use `latest`.
- Postgres listens on `localhost:5432` only (no `0.0.0.0` exposure beyond Docker's default).
- Default credentials in `.env.example` should be obviously fake (`qeetro_dev`/`qeetro_dev_password`).
- Compose v2 syntax (no top-level `version:`).
- Health checks must report healthy within 10 seconds.

### Security Considerations
- No real secrets committed. `.env` is gitignored; only `.env.example` is committed.
- Containers run as non-root where the image supports it.
- Database password warned about in README: "for local dev only — never reuse for cloud."

### Performance Considerations
- Postgres `shared_buffers` and `work_mem` left at defaults for local dev.
- Volume size unbounded in dev (host disk only).

### Edge Cases
- Compose must clean up cleanly on `db:down -v` without leaving dangling networks.
- If port 5432 or 6379 is in use, Compose should surface a clear error (do not auto-reassign).
- Apple Silicon must work — verify both images have arm64 variants.
