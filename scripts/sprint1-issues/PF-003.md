## Content

### Description
Set up linting, formatting, and commit hygiene so every PR meets the same baseline without manual review effort.

### Business Context
A consistent style baseline lowers code review cost across an entire MVP. We need a shared ESLint config, Prettier, and an opt-in pre-commit hook before the first real source code lands in PF-004/PF-005.

### Problem Statement
There is no enforced style or lint policy yet. Without it, the codebase will accumulate stylistic drift that costs review time without producing value.

### Scope
- `packages/eslint-config` workspace exposing:
  - `base.js` (Node + TypeScript baseline).
  - `nextjs.js` (Next.js + React Hooks rules).
  - `nestjs.js` (Node + decorator-friendly rules).
- Prettier config at repo root (`.prettierrc.json` and `.prettierignore`).
- Repo-root `eslint.config.js` (flat config) selecting per-app configs.
- Optional `husky` + `lint-staged` for `pre-commit` running Prettier + ESLint on staged files.
- Repo-root scripts in `package.json`:
  - `lint`: ESLint over the repo.
  - `lint:fix`: ESLint with `--fix`.
  - `format`: Prettier write.
  - `format:check`: Prettier check.
- Conventional commits encouraged but not enforced; add a short note in `docs/contributing.md` (created here if needed).

### Technical Notes
- ESLint v9 flat config; do not use `.eslintrc` legacy.
- Configure `eslint-plugin-import` with boundary rules coordinated with PF-002.
- Allow `// eslint-disable-next-line` only when justified inline.
- Do not adopt overly strict rules at this stage (e.g. ban `console`). The principle is "make CI fail on obvious mistakes, not on style preference."

### Security Considerations
- No secrets in lint config.
- Pre-commit hook must not run external network calls.

### Edge Cases
- Husky should not block commits when the user opts out (`HUSKY=0 git commit`).
- Lint-staged should not touch generated files (`*.gen.ts`, Prisma generated client).

## Delivery

### Acceptance Criteria
- [ ] `pnpm lint` succeeds on a clean checkout with zero errors.
- [ ] `pnpm format:check` succeeds on a clean checkout.
- [ ] A deliberately badly-formatted file fails `pnpm format:check`.
- [ ] A deliberately unused-import is flagged by `pnpm lint`.
- [ ] Pre-commit hook (if installed) runs Prettier + ESLint on staged files only.
- [ ] `packages/eslint-config` consumed by at least one app.

### Testing Requirements
- Manual: run `pnpm lint` and `pnpm format:check` on the clean repo and on a deliberately broken file.
- CI (PF-009) must run `pnpm lint` and `pnpm format:check`.

### Definition of Done
- Branch merged into `develop`.
- Style choices documented in `packages/eslint-config/README.md`.
- Sprint 1 board column updated to Done.
