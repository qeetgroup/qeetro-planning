## Content

### Description
Create the Next.js App Router shell for `apps/web` so all future frontend features have a stable layout, route structure, and shared design-system entry point.

### Business Context
qeetro's product principle is "execution workspace first, no marketing chrome." The first page a user sees after login should be the app, not a landing page. This shell is the substrate for every screen that follows (auth screens in Sprint 2, project/issue UI in Sprints 3–4, etc.).

### Problem Statement
There is no web app yet. We need a deployable Next.js project that renders a home route, supports Tailwind + shadcn/ui, has correct fonts, and uses route groups that anticipate auth-protected vs public surfaces.

### Scope
- Next.js 15+ App Router under `apps/web`.
- `src/app/` with route groups: `(auth)/`, `(app)/`, `(marketing-later)/` (the last one empty for now).
- TailwindCSS configured with the qeetro design tokens (color palette, font stack, spacing scale — minimal defaults are fine; full design system is a later issue).
- shadcn/ui bootstrap (`components.json`, base `Button`, `Input`, `Card` primitives — minimum viable).
- Global `app/layout.tsx` with HTML lang, font, theme provider stub.
- Health page at `/healthz` returning a 200.
- Placeholder `/` route showing "qeetro web shell".
- TanStack Query provider wired (no queries yet).
- Zustand store skeleton created but empty.
- TypeScript config extends `packages/tsconfig/nextjs.json`.

### Technical Notes
- Use the App Router exclusively (no Pages Router code).
- Use Server Components by default; mark client components with `"use client"`.
- Tailwind CSS v4 if compatible with Next.js 15; otherwise pin v3.
- Font: pick one stack (Inter or Geist) and document it.
- No business logic in this shell — only layout and provider plumbing.
- Add a basic ErrorBoundary and NotFound page.

### UX Notes
- Execution workspace first: home route is the app shell, not a landing page.
- No animations beyond loading-state defaults.
- Layout must be stable: no layout shift when content loads.

### API Notes
- Web shell calls no APIs yet. API client setup is part of `packages/api-client` from PF-006.

### Database Notes
N/A.

### Security Considerations
- No client-side secrets.
- Set `Content-Security-Policy` via middleware stub (real CSP comes in Sprint 9 SEC-002).
- Cookies will be `httpOnly` + `secure` once auth lands.

### Performance Considerations
- Use the production build for the smoke test (`next build && next start`).
- First-load JS budget: keep the shell under 150 KB gzip on `/`.

### Edge Cases
- The `(marketing-later)/` route group must not break the build when empty.
- 404 page must render correctly.
- Dark mode toggle stubbed but not required to work.
