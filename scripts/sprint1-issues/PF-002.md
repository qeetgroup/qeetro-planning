## Content

### Description
Configure shared TypeScript build boundaries so packages can depend on each other safely, but apps cannot leak into packages and circular imports are detected before merge.

### Business Context
Shared types are the spine of a modular monolith. They reduce drift across `apps/web`, `apps/api`, and `apps/worker`. Without enforced boundaries, packages will eventually import from apps and the modular property of the monolith collapses.

### Problem Statement
No `tsconfig` exists. Every package will need a TypeScript build config, and we need to settle the question of: project references vs single tsconfig, path aliases, and strictness flags — once, centrally — so future packages inherit safe defaults.

### Scope
- `packages/tsconfig` workspace package exposing:
  - `base.json` (strict mode, no implicit any, isolated modules, ES2022 target, NodeNext module resolution).
  - `nextjs.json` extending base for the web app.
  - `nestjs.json` extending base for the API and worker.
  - `library.json` extending base for shared packages.
- Each app/package extends the appropriate tsconfig.
- Path aliases declared at the package level only (no global aliasing across the monorepo).
- Project references enabled so `tsc -b` resolves cross-package builds.
- ESLint or `eslint-plugin-import` boundary rules to detect:
  - Apps importing apps.
  - Packages importing apps.
  - `packages/domain` importing Prisma, Nest, or React.
  - `packages/ui` importing backend packages.

### Technical Notes
- Use `composite: true` on packages that are referenced.
- Prefer NodeNext module resolution for forward compatibility.
- Strict flags: `strict`, `noUncheckedIndexedAccess`, `noImplicitOverride`, `exactOptionalPropertyTypes`.
- Output `dist/` is gitignored.
- Coordinate ESLint boundary rules with PF-003.

### Security Considerations
N/A.

### Performance Considerations
- Project references give incremental builds. Cold builds should stay under 30 seconds for the skeleton.

### Edge Cases
- Next.js may need a slightly looser tsconfig (e.g. `jsx: preserve`); document the override in `apps/web/tsconfig.json`.
- Type-only imports (`import type`) should not be flagged by boundary rules.

## Delivery

- [ ] An intentional invalid import (`apps/web` importing from `apps/api`) is caught by ESLint or `tsc` and fails CI.
