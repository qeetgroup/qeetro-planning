## Content

### Description
Bootstrap the foundational shared packages used by both apps: UI primitives, config, API client, and versioned event contracts.

### Business Context
Cross-app contracts need exactly one home. If web and API duplicate enums, DTOs, or event payloads, drift is guaranteed. These packages are the contracts that keep the modular monolith coherent.

### Problem Statement
Sprint 2 introduces DTOs that web and API both consume, events that the activity feed and notifications consume, and UI primitives that every screen depends on. Those homes must exist now.

### Scope
- `packages/ui`:
  - shadcn/ui-based design system primitives (re-exported `Button`, `Input`, `Card`, `Dialog`, `DropdownMenu`).
  - Tailwind preset published from this package and consumed by `apps/web`.
- `packages/config`:
  - Typed env schema using `zod` (consumed by both web and API).
  - `loadConfig()` helper that throws on missing required env vars.
- `packages/api-client`:
  - Typed REST client stub generated from API DTOs (manual interfaces for now; OpenAPI codegen lands later).
  - Fetch wrapper with auth header injection placeholder.
- `packages/event-contracts`:
  - One reference event schema (`PingEvent.v1`) using `zod` so the pattern is clear.
  - Versioning convention documented in `README.md`: `<domain>.<event>.v<N>`.
- `packages/domain`:
  - Pure types only — no Prisma, no Nest, no React imports.
  - Example: shared brand types like `OrganizationId`, `UserId`.
- `packages/utils`:
  - Pure helpers (e.g. `result.ts` for a typed Result pattern, `slug.ts`).
- `packages/logger`:
  - Logger interface only; concrete implementation lands in PF-012.
- `packages/permissions`:
  - Permission constant strings only; actual policy engine lands in Sprint 2 (PERM-002).
- `packages/testing`:
  - Vitest base config and a `createTestContext()` factory stub.

### Technical Notes
- Every package has its own `package.json`, `tsconfig.json` extending `packages/tsconfig/library.json`, and `src/index.ts`.
- No package imports from `apps/*`.
- No business logic in shared packages — they hold types, contracts, and pure helpers only.
- `packages/event-contracts` MUST use schema validation (zod) so consumers cannot drift silently.

### Security Considerations
- `packages/config` `loadConfig()` must never log raw secrets, even on validation failure — log the env key name only.

### Performance Considerations
N/A.

### Edge Cases
- Avoid TS path aliases that cross package boundaries; use `workspace:*` versions in package.json instead.
- `packages/domain` must compile in a strict isolated environment (no Node-only globals).
