## Content

### Description
Scaffold a pnpm workspace monorepo that hosts every qeetro application and shared package under one repo with predictable boundaries.

### Business Context
qeetro is a modular monolith. Every other Sprint 1 ticket (web shell, API shell, shared packages, Docker, Prisma, CI) assumes the monorepo layout already exists. Without it, work cannot proceed in parallel and dependency rules cannot be enforced.

### Problem Statement
There is no buildable repo today. We need a single command that installs all workspaces, a single command that builds them, and a directory layout that matches the architecture blueprint so contributors land in the right place.

### Scope
- `pnpm-workspace.yaml` listing `apps/*` and `packages/*`.
- Root `package.json` with workspace-aware scripts: `dev`, `build`, `lint`, `typecheck`, `test`, `clean`.
- Directory skeleton:
  - `apps/web`, `apps/api`, `apps/worker`
  - `packages/api-client`, `packages/config`, `packages/database`, `packages/domain`, `packages/event-contracts`, `packages/eslint-config`, `packages/logger`, `packages/permissions`, `packages/testing`, `packages/tsconfig`, `packages/ui`, `packages/utils`
  - `infra/docker`, `infra/terraform`, `scripts`
- `.nvmrc` or `engines` block pinning Node 20 LTS.
- `.gitignore` for Node, Next.js, Prisma, pnpm.
- Each empty package has a minimal `package.json` with `name`, `version`, `private: true`.

### Technical Notes
- pnpm `>=9` required. Use `pnpm-workspace.yaml` (not npm/yarn workspaces).
- No app may import another app. Apps may import packages. Packages may not import apps.
- Reference [02-architecture-blueprint.md §6](../../docs/planning/02-architecture-blueprint.md) for the canonical layout and dependency rules.
- Do not yet add real source files inside apps/ or packages/ — that belongs to PF-002..PF-006.
